# コードコメントのルール

## 原則

- コメントは原則書かない。わかりにくいコードは、命名・関数への切り出し・変数化で直す。
- 書いてよいのは、コードを直しても消せない「なぜ」だけ。
  - ブラウザのバグや仕様の回避（対象ブラウザを明記する）
  - 外部ライブラリ・API・CMSの制約
  - 仕様や要望によって意図的にそうしている、一見不自然な実装
- 他ファイル・他箇所の値や構造に言及しない。依存関係は、変数や設定を共有してコードで表す。
- コメントは日本語で書く。
- 注記タグは `TODO:` `FIXME:` `NOTE:` `HACK:` のみ使う。`HACK:` には削除してよい条件を書く。

## 既存コードを編集するとき

- 変更していない箇所にコメントを足さない。
- 変更内容や経緯を説明するコメント（「〜に変更」「〜を追加」など）は書かない。
- 自分の変更によって内容が古くなったコメントは、修正するか削除する。

## 目印コメント

位置を見失わないためのコメントは、次の場面に限って使う。

- HTML: 閉じタグコメントは、開始タグが画面外に出るほど長いブロックにだけ付ける。形式は `<!-- /.class名 -->`。
- CSS: セクション区切りは、1ファイルに複数のブロックやコンポーネントがある場合にだけ使う。
- JavaScript: 区切りコメントは使わない。必要に感じたら、ファイルや関数を分ける。

## 公開されるコメント

- ブラウザから見えるコメントに、公開されて困る内容を書かない。
- CMSテンプレート内の運用メモは、出力されない形式で書く（Movable Typeなら `<mt:Ignore>`）。
